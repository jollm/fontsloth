#+TITLE: Lazy outlining results (2026-11-07)

Note: these numbers were captured from interpreted source. See
=benchmarks/compiled.org= for byte-compiled results.
#+OPTIONS: toc:nil ^:{} \n:t

First lazy-outlining implementation, measured against
=benchmarks/baseline.org= (eager). Default is now lazy. Eager mode is
selected with `:font-settings (fontsloth-font-settings-create
:lazy-outline? nil)` or =FONTSLOTH_BENCH_LAZY=0=.

* Environment

Same as the baseline: Emacs 31.1, Linux 7.2.14 x86_64, Ryzen 9 5900X,
32.0 px raster, SF Pro raster capped at 200 code points.

* Command

#+begin_src shell
FONTSLOTH_BENCH_LAZY=1 \
FONTSLOTH_BENCH_FONT=/gnu/store/zqrwsqs1lfk1ag3ni1zhv04skc4q36hc-font-apple-sf-pro-20.0d8e1/share/fonts/truetype/SF-Pro.ttf \
FONTSLOTH_BENCH_RASTER_LIMIT=200 \
maak benchmark
#+end_src

* Results

| Font | Mode | Load | Load alloc | Load retained | Force all | Force alloc | Force retained |
|------+------+------+------------+---------------+-----------+-------------+----------------|
| Plex subset | eager | 1.908s | 561.05 MB | 1.90 MB | — | — | — |
| Plex subset | lazy | 0.582s | 186.73 MB | 0.77 MB | 1.365s | 374.35 MB | 1.90 MB |
| SF Pro | eager | 63.331s | 14,627.57 MB | 314.53 MB | — | — | — |
| SF Pro | lazy | 17.460s | 6,327.05 MB | 77.89 MB | 45.500s | 8,301.97 MB | 314.33 MB |

For lazy mode, "force all" calls `fontsloth-font-all-glyphs`, which
outlines every mapped glyph. The raster passes only touch the selected
code points (200 for SF Pro), so a partial-use workload pays only for
the glyphs it actually renders.

* Interpretation

- Loading lazily is ~3.6× faster and retains ~4× less heap for SF Pro:
  17.5s / 78 MB vs 63.3s / 315 MB.
- Outlining everything later costs roughly the difference, so the total
  time and allocation for a full-outline workload is approximately the
  same: 62.96s vs 63.33s, and ~14.6 GB allocated in both modes.
- The win is therefore workload-dependent: applications that use a
  small subset of a large font avoid most of the outline cost and
  retained memory.
- Rasterization itself is unchanged (~0.17s / 37 MB for 200 SF Pro
  glyphs) and remains cheap relative to parsing/outlining.
- The parser data (tables + raw bytes) is now retained per live font in
  a weak registry. SF Pro lazy load retains ~78 MB, which is roughly
  the parsed-table footprint. Dropping raw bytes after parsing is the
  next likely reduction.

* Correctness

The full suite (including the golden outline hashes, parser-vs-high-level
comparison, bounds/orientation invariants, raster stability, and cache
round-trip/reparse tests) passes with lazy outlining enabled by default.


* After dropping raw bytes (same day)

The loaded `fontsloth-otf-font` now keeps only the parsed tables and the
source SHA-1. The raw bytes are released after parsing.

| Font | Mode | Load | Load alloc | Load retained | Force all | Force retained |
|------+------+------+------------+---------------+-----------+----------------|
| Plex subset | lazy | 0.551s | 186.73 MB | 0.74 MB | 1.257s | 1.90 MB |
| SF Pro | lazy | 17.379s | 6,327.05 MB | **59.02 MB** | 45.973s | 314.33 MB |

SF Pro lazy retained heap drops from 77.89 MB to 59.02 MB, matching the
19.8 MB source file size. Parsing time and allocation are unchanged,
and the full-outline retained figure remains dominated by the glyph
data (~314 MB).


* Byte-compiled repeat (2026-11-07)

Measured at commit =f5796ea= with byte-compiled sources.  Both modes use
the same benchmark binary. =BENCH_LAZY=0= selects eager settings and
=BENCH_LAZY=1= selects lazy settings.

| Font | Mode | Parse | Load | Force all | Load retained | Force retained |
|------+------+-------+------+-----------+---------------+----------------|
| SF-Pro.ttf | eager | 0.820s / 151.13 MB | 8.126s / 879.79 MB | — | 314.75 MB | — |
| SF-Pro.ttf | lazy | 0.923s / 151.13 MB | 0.791s / 151.33 MB | 7.152s / 728.45 MB | 78.10 MB | 314.34 MB |
| Plex subset | eager | 0.005s / 3.75 MB | 0.094s / 9.89 MB | — | 1.91 MB | — |
| Plex subset | lazy | 0.005s / 3.75 MB | 0.005s / 3.74 MB | 0.060s / 6.15 MB | 0.77 MB | 1.91 MB |

Compiled lazy load is ~10× faster and retains ~4× less than compiled
eager load. Full outlining via =force-all= brings the cumulative cost
back near the eager level.
